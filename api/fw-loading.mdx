---
title: "fw_loading"
description: "Covers the screen from the moment someone connects until the character list is ready, and again after they pick a character until that ped is dressed."
---

Runs in the player's game. Two covers:

- From the moment someone connects until the character list is on screen. That page starts with them. It is not a second card stacked on the game's own screen.
- After they pick a character, or finish creating one, until the body, clothes, and weapons are on.

The connect page is a custom screen, not a game cutscene. `FWConfig.connectVideo` is a file in this resource, such as `html/intro.webm`, played behind the words. Leave it empty and set `FWConfig.connectSlideshow` instead — a list of image files, such as `html/slides/01.webp`, crossfaded in order every `connectSlideshowMs`. Leave both empty and the page stays plain words on a dark background. The page shuts down exactly once, when the character list is ready to be seen.

The spawn cover, after a character is chosen, tries a random entry from `FWConfig.cutscenes` first — one of the game's own cutscenes, such as `Cutscene_MpIntro`. It ends as soon as the ped is fully loaded (body, clothes, and weapon kit), not when the movie itself ends, so a fast load is never stuck watching the rest of a cutscene. If the cutscene asset never loads, `FWConfig.video` plays instead; if that is also empty or missing, the native loading card is shown. `minHoldMs` is the shortest the spawn cover stays up regardless. `maxWaitMs` is how long to wait for the clothes and the weapons before showing the ped anyway. `sceneWaitMs` is how long to stream the spawn, in milliseconds — the stream also stops when the ground around the player is loaded. `sceneRadius` is how far around the spawn to stream, in metres. The cover puts the ped back on screen after it comes down. A visible set while the cover is up does not remain.

`fw_core` hands the connect page its words before it lets the player in. The page closes when the character list is ready to be seen: it calls `loadingComplete`, and that call runs `ShutdownLoadingScreenNui`.

`fw_creator` already calls these when a character is chosen. Use them yourself when you move someone a long way and need the same cover.

## Calls

`Show`, `Hide`, `ReleaseConnectScreen`, `StreamScene`, and `MaxWaitMs` run in the player's game. `Handover` runs on the server.

### Show

Puts the cover up. `kind` is `connect` or `spawn`. Anything else is treated as `spawn`. Calling it again for the same kind does not restart the timer.

On connect, the loadscreen page is already up on its own from the moment the player joined. This call does not stack a second card on it. `spawn` tries the cutscene, then the video, then the native loading card, in that order.

```lua
--- Shows the connect or spawn cover.
---@param kind string connect or spawn
---@return nil
exports.fw_loading:Show(kind)
```

```lua
exports.fw_loading:Show('spawn')
```

### Hide

Takes the cover down. If it has been up for less than `minHoldMs`, this call waits out the rest. Ends whichever one of the cutscene, the video, or the native card is currently showing. Safe to call when nothing is showing.

```lua
--- Hides the cover, after the minimum hold.
---@return nil
exports.fw_loading:Hide()
```

```lua
exports.fw_loading:Hide()
```

### ReleaseConnectScreen

Asks the connect page to close, once the character list is ready to be seen. This retries for a few seconds if the page does not drop on the first try, and warns in the server window's F8-visible client log if it never does, instead of leaving the page silently stuck.

```lua
--- Closes the connect page so the character list can fade in.
---@return nil
exports.fw_loading:ReleaseConnectScreen()
```

```lua
exports.fw_loading:ReleaseConnectScreen()
```

### Handover

Runs on the server, during `playerConnecting`. `deferrals` is the join handshake. `playerId` is the player's number for this visit. Call it before `deferrals.done`, or the connect page never receives the words. `fw_core` already does this on the way in. A script that replaces that check has to call it too.

The page receives the player's name, the server name, `gamemode`, `title`, `subtitle`, the connect video file name when one is set, and the slideshow image list and interval when one is set instead.

```lua
--- Hands the connect page its words. Call this before deferrals.done.
---@param deferrals table
---@param playerId integer
---@param fallbackName string|nil
---@return nil
exports.fw_loading:Handover(deferrals, playerId, fallbackName)
```

```lua
AddEventHandler('playerConnecting', function(playerName, _setKickReason, deferrals)
    deferrals.defer()
    Wait(0)
    exports.fw_loading:Handover(deferrals, source, playerName)
    deferrals.done()
end)
```

### StreamScene

Streams the world around a point. `x`, `y`, and `z` are metres. It stops when that spot is loaded, when the ground around the player is loaded, or when `sceneWaitMs` runs out. Comes back yes when the spot loaded.

```lua
--- Streams the world around a spawn.
---@param x number
---@param y number
---@param z number
---@return boolean loaded
exports.fw_loading:StreamScene(x, y, z)
```

```lua
local loaded = exports.fw_loading:StreamScene(x, y, z)
if not loaded then
    print('the spot did not finish streaming')
end
```

### MaxWaitMs

How long a spawn may wait for clothes and weapons, in milliseconds. A bad config value comes back as `15000`.

```lua
--- The spawn wait, in milliseconds.
---@return integer
exports.fw_loading:MaxWaitMs()
```

```lua
local waitMs = exports.fw_loading:MaxWaitMs()
```

## Messages

The cover listens for these. It does not send them. They are documented on the resource that sends them.

- [fw_creator:bodyReady](/api/fw-creator#messages-the-menu-uses) — the saved body is on the ped. The cover waits for this first.
- [fw_clothing:applied](/api/fw-clothing#fw_clothingapplied) — the clothes are on, or there were none. `fw_creator:bodyBare` means the same thing.
- [fw_creator:appearanceReady](/api/fw-creator#messages-the-menu-uses) — the cover asks for the weapon kit, after the body and the clothes.
- [fw_weapons:kitApplied](/api/fw-weapons#fw_weaponskitapplied) — the kit is on the current ped. The cover comes down after this, or when the wait runs out.
