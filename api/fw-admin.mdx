Runs on the server. Ask this before you do something only an admin should do.

An admin is a player named in `permissions.cfg`. Being able to open the txAdmin website does not make them an admin. Setting their account label to `admin` in the database does not make them an admin either.

```
add_ace group.admin fw.admin allow
add_principal identifier.license:YOUR_LICENSE group.admin
```

`server.cfg` loads that file with the line `exec permissions.cfg`. After you edit it, restart the server, or type `exec permissions.cfg` in the server window. fw_admin reads `permissions.cfg` again on every check, so a player who is already in the game picks up the change right away. They do not have to leave and join again.

`fw.admin` passes every admin check, including a smaller one such as `fw.admin.kick`. A helper who should only kick gets that smaller permission, and does not get `fw.admin`.

Type `fw_admin` and a `source` in the server window. It writes INFO lines with that player's ids so you can copy the `license:` line.

## Exports

### IsReady

Runs on the server. Says yes once fw_admin has finished starting: `fw_core` answered its own `IsReady` as yes, and fw_admin checked in with it.

You do not need to wait for this before calling `IsAdmin` or `HasPermission`. Those two already work as soon as fw_admin starts, even in the moment it is still waiting on `fw_core` underneath. `IsReady` is here for a script that only wants to confirm fw_admin itself started cleanly, for example after seeing `[fw_admin] ready` in the server window.

```lua
--- True once fw_admin has finished starting.
---@return boolean ready
exports.fw_admin:IsReady()
```

### IsAdmin

Runs on the server. Yes for the server window, and yes for a player who has `fw.admin`. No for everyone else, and no if you pass something that is not a real `source`.

```lua
--- True when this player may use admin tools.
---@param source integer `source`, or 0 for the server window
---@return boolean
exports.fw_admin:IsAdmin(source)
```

`source` is the client id of the player who triggered the event. It changes every time they join. Use `0` when the check is for the server window itself, not a player.

```lua
if not exports.fw_admin:IsAdmin(source) then
    return
end
```

### HasPermission

Runs on the server. Yes when the player has `fw.admin`, or has the one smaller permission you name. A permission that does not start with `fw.admin.` is always no — this will not answer questions about any other server permission, admin or not.

```lua
--- True when the player has fw.admin, or the smaller permission you pass.
---@param source integer `source`, or 0 for the server window
---@param permission string|nil such as 'fw.admin.kick'
---@return boolean
exports.fw_admin:HasPermission(source, permission)
```

The server window passes any `fw.admin.` permission you name. A player who only has `fw.admin.kick` passes this check for that name, and `IsAdmin` is still no for them.

```lua
if not exports.fw_admin:HasPermission(source, 'fw.admin.kick') then
    return
end
```

## Commands

| Command | Who | What happens |
| --- | --- | --- |
| `/admin` | A player in the game | Opens the admin screen when they have `fw.admin`. Anyone else gets a log line saying they are not an admin. |
| `/tpm` | A player in the game | Moves them to the waypoint on their map when they have `fw.admin`. Anyone else gets a log line saying they are not an admin. Set a waypoint first. If the ground under it cannot be found, the log says so and they stay where they are. |
| `/fw_admin` | The player who types it | The log says whether they are an admin. It does not print their ids. |
| `fw_admin` | Server window | Prints whether fw_admin is ready. |
| `fw_admin <serverId>` | Server window | Prints whether that player is an admin, and their ids, so you can copy the `license:` line into `permissions.cfg`. |
| `admin` (no slash) | Server window | Prints that `/admin` is for a player in the game. It does nothing else. |
| `tpm` | Server window | Prints that `/tpm` is for a player in the game. It does nothing else. |

`/admin` opens the admin screen. It needs `fw.admin`. A smaller permission such as `fw.admin.kick` does not open it. The screen uses the art in `fw_admin` and the crock and Hapna fonts from [fw_menu](/api/fw-menu), so `fw_menu` has to be started. Escape or Close leaves the screen. While it is open, that character stays still. The same words that go to the log also sit on the line under the panel.

Page Up opens a smaller menu in the corner. The mouse stays on the game. Up and down move. Left and right change the list. Enter runs the line. Backspace closes it, and Page Up again closes it too. The game's key bindings list that key as Admin self menu, so it can be changed there. If the big screen is already open, Page Up does nothing.

The left side lists the sections. The middle is the list for that section. The right side is the record you chose. Close on that record clears the right side. It does not leave `/admin`.

- **Dashboard.** How many people are online, and their names. Choose a name and their actions open on the right. You stay on Dashboard.
- **Players.** The search box filters the list as you type. Refresh asks for the list again. Each row is the name, the server number, and the dollars they are carrying. A dash is shown when cash cannot be read. Unban is a license field under this list, because it is a license and not a person. Choose a person and the actions open on the right: go to them, bring them, send them back, watch them, freeze them, fill their health, revive them, give an item, give dollars, set a reputation score, kick, or ban. Give item searches the item list as you type. The box shows the words players see, such as Apple. Saving still sends the internal name, such as `consumable_apple`. A label that matches one item is enough. Several matches need a choice. Kick and ban ask you to confirm first. Watching someone closes the screen, so the camera is yours. Open `/admin` again to stop watching.
- **Missions.** Search the missions, then choose one. Unions and Seasons are the other two tabs. A draft can be saved before it is ready. Publish marks a field that is still wrong. Disable stops new accepts. An open run can still be finished. Duplicate asks for a new id. A new mission is five steps: the job, who offers it, the stages in order, the pay, then a look at the path. Save and Publish are on that last step. The server checks `fw.admin.missions` before it writes. How a mission is stored is in [fw_missions](/api/fw-missions). A season copies standing and mission progress for the unions it names, then sets that standing to 0 and clears those mission rows. Dollars stay in the satchel. A season that already ran cannot be edited.
- **Stores.** Search the shops, then choose one. The shop stays in the list, and the record opens on the right: the name, the type, the town, the clerk, the hours, the place, the shelf, and the buyback. The item boxes on a shelf line, a buyback line, and a trade line use that same search. Type apple and it finds `consumable_apple`, or a label of Apple. Underscores in the internal name count as spaces. Up to eight matches sit under the box. Choosing one, or typing a label that matches one item, saves the internal name. A word that matches nothing is refused the same way an unknown item is refused. Add trade under a shelf line lists what pays for that pile instead of dollars. Close clears the right side and leaves what you typed unsaved. Here fills the place from where you are standing. Save writes it. Open store closes this screen and opens that counter. If someone is already there, the counter does not open, and `/admin` brings this screen back. Apply template copies the shelf you pick onto this shop. Reset shelf copies the shelf named by this shop's type. Delete asks first. New shop fills the right side. It asks for an id, a type, a name, a clerk model, and a place, then copies that type's saved shelf. Templates switches the list to the shared shelves. New shelf fills the right side and asks for an id. Save writes that shelf and does not change shops that already copied it. Delete asks first. The server checks `fw.admin.stores` before it writes, and before Open store. How a shop is stored is in [fw_stores](/api/fw-stores).
- **Teleports.** Waypoint, Guarma, and Return are the list. The coordinates you type, and the hint, are on the right. Waypoint is the same move as `/tpm`.
- **Coords.** The four copy lines are the list. Where you are standing is on the right. Copy is the plain numbers, a `vector3`, a `vector4`, or the heading. The same line is written to the F8 log and on the line under the panel. The clipboard call is `exports.vorp_lib:copyToClipBoard`. If `vorp_lib` is not started, nothing is copied and the log says the clipboard is not available.

Statistics, Whitelist, Reports, Admins, Logs, Admin Chat, Live Map, Blips, Spawner, Server Settings, and Resource Lookup are in the list and say they are not on the server yet. They do not run anything.

The small menu has three lists.

- **Player.** God mode, no clip, invisible, unlimited ammo, fill health, fill health and stamina, and revive. A toggle shows On or Off. No clip moves with W and S, up with Q, down with Z. Shift changes the speed. Delete stops it. Turning no clip on closes the small menu, so those keys work. Page Up opens it again.
- **Teleport.** Waypoint, Guarma, and return.
- **Display.** Show coordinates draws them on the screen while you play. The copy lines are the same four as Coords.

Giving an item uses [fw_inventory](/api/fw-inventory) `AddItem`. The count is from 1 to 500. Giving dollars uses [fw_money](/api/fw-money) `AddCash`. The amount is from 1 to 100000. Both land in the satchel of the character they are playing. If that character is not selected, or the satchel has no room, nothing is given and the log says why. The dollars in the player table come from [fw_money](/api/fw-money) `GetCash`.

Reputation lists each class from [fw_reputation](/api/fw-reputation). The line shows the standing and the score. Type a whole number from 0 to 1000 and save it. That uses `Set`. If that character is not selected, or the number is refused, nothing is saved and the log says why. Back returns to that person.

A ban uses the hours field. You confirm before it is saved. `0` does not expire. The longest timed ban from the screen is 8760 hours, which is one year. The screen saves it with [fw_core](/api/fw-core) `SetBan`, then removes them from the server. Unban uses the license, including `license:` at the front. A hex id on its own is treated as a Rockstar license.

Bring remembers where that person was standing, on the server. Send back uses that spot. A second bring keeps the first spot. Guarma remembers where you were standing the same way. If there is no remembered spot, back from Guarma uses a mainland spot near Saint Denis.

The server checks the permission again before it does the thing. A screen left open by someone who loses admin will not let them teleport, kick, or give.

## Smaller permissions

`fw.admin` passes every check below. Give a helper only the line they should have. They still cannot open `/admin` without `fw.admin`. The check matters when their game asks the server directly.

| Permission | What it allows |
| --- | --- |
| `fw.admin.players` | The player list, go to, bring, send back, freeze, fill health, revive, and spectate. |
| `fw.admin.kick` | Kick. |
| `fw.admin.ban` | Ban and unban. |
| `fw.admin.give` | Give an item, or give dollars. |
| `fw.admin.reputation` | Read and set a reputation score. |
| `fw.admin.stores` | List, read, save, create, delete, reset, apply a shelf, and open a shop. List, read, save, create, and delete a shared shelf. |
| `fw.admin.missions` | List, save, publish, disable, and duplicate a mission. Save or remove a union. Save or end a season. |

Self tools, the waypoint, typed coordinates, Guarma, and copy coordinates need `fw.admin`.

```
add_ace group.helper fw.admin.kick allow
add_principal identifier.license:YOUR_LICENSE group.helper
```

## Events

These are networked events, sent with `RegisterNetEvent` and `TriggerServerEvent` / `TriggerClientEvent` — not `AddEventHandler`. None of them are queued: the listening side has to already be running when the event is sent, or it is simply missed. fw_admin's own client and server scripts are always running together while the resource is started, so this mostly matters if your own script triggers one of them.

A new admin tool should check `IsAdmin` or `HasPermission` itself first, then do its own work. Prefer `AddItem`, `AddCash`, and `SetBan` when you are giving or banning from your own script. The events below belong to the screen. The server ignores an ask when the permission is no.

You can open the same screen from your own server script:

```lua
if not exports.fw_admin:IsAdmin(source) then
    return
end
TriggerClientEvent('fw_admin:openMenu', source)
```

### fw_admin:openMenu

Networked, server to the client. Opens the admin screen for that player. Their game shows "The admin screen is not running." in the log instead if that screen has not loaded.

```lua
--- Networked. Trigger this from the server once you have already checked IsAdmin.
---@param source integer the player to open the screen for
TriggerClientEvent('fw_admin:openMenu', source)
```

Page Up asks the server before the small menu opens. Another script can ask the same way, after `IsAdmin` is yes.

```lua
--- Networked. The server ignores it unless IsAdmin is yes for the sender.
TriggerServerEvent('fw_admin:requestSelfMenu')
```

```lua
--- Networked. Opens the small self menu for that player.
---@param source integer
TriggerClientEvent('fw_admin:openSelf', source)
```

### fw_admin:log

Networked, server to that client. The screen writes the same line in the server window and in their F8 log. When the screen is open, that line is also shown under the panel. `level` is `info`, `warn`, or `error`.

```lua
--- Networked. Sent by fw_admin with a line for that player's F8 log.
---@param message string
---@param level string|nil
TriggerClientEvent('fw_admin:log', source, message, level)
```

### Asks from the screen

Networked, the client to the server. `target` is the other `source`. The server reads where people are standing itself. Send back cannot be aimed at a spot the game invented.

| Event | Permission | Arguments |
| --- | --- | --- |
| `fw_admin:requestPlayers` | `fw.admin.players` | None. The reply is `fw_admin:playerList`. |
| `fw_admin:requestItems` | `fw.admin` | None. The screen asks when `/admin` opens. The reply is `fw_admin:itemList`, sent to that player only. Each row is `name` and `label`. The full item definition stays on the server. |
| `fw_admin:goTo` | `fw.admin.players` | `target` |
| `fw_admin:bring` | `fw.admin.players` | `target` |
| `fw_admin:sendBack` | `fw.admin.players` | `target` |
| `fw_admin:freeze` | `fw.admin.players` | `target`. Choose it again to let them move. |
| `fw_admin:heal` | `fw.admin.players` | `target`, `stamina`. `stamina` true also fills stamina. |
| `fw_admin:revive` | `fw.admin.players` | `target` |
| `fw_admin:spectate` | `fw.admin.players` | `target`. The same target again stops it. |
| `fw_admin:spectateLost` | `fw.admin` | None. Their game sends this when the person can no longer be watched. |
| `fw_admin:kick` | `fw.admin.kick` | `target` |
| `fw_admin:ban` | `fw.admin.ban` | `target`, `hours`. `0` does not expire. |
| `fw_admin:unban` | `fw.admin.ban` | `license` |
| `fw_admin:giveItem` | `fw.admin.give` | `target`, `name`, `count` |
| `fw_admin:giveCash` | `fw.admin.give` | `target`, `amount` |
| `fw_admin:self` | `fw.admin` | `tool`, and sometimes `false` to force it off. `tool` is `god`, `noclip`, `invis`, `ammo`, `heal`, `stamina`, or `revive`. |
| `fw_admin:teleportWaypoint` | `fw.admin` | None. |
| `fw_admin:teleportCoords` | `fw.admin` | `x`, `y`, `z` |
| `fw_admin:teleportGuarma` | `fw.admin` | None. |
| `fw_admin:teleportReturn` | `fw.admin` | None. |
| `fw_admin:copyCoords` | `fw.admin` | `kind`: `xyz`, `vector3`, `vector4`, or `heading`. |
| `fw_admin:requestSelfMenu` | `fw.admin` | None. The reply is `fw_admin:openSelf`. |
| `fw_admin:stores` | `fw.admin.stores` | One table. `op` is `list`, `read`, `save`, `create`, `delete`, `reset`, `apply`, `open`, `templateList`, `templateRead`, `templateSave`, `templateCreate`, or `templateDelete`. Shop ops other than `open` reply with `fw_admin:storeData`. `apply` also sends `templateId`, the shelf to copy onto that shop. `open` does not write the shop. The server sends `fw_admin:openStore` to that admin, with the store id. That client closes the admin screen and runs `fw_stores:open`. A template op uses the same reply. `templateSave` does not change shops that already copied that shelf. |

```lua
--- Networked. Sent by the admin screen. The server ignores it unless that player may do it.
---@param target integer
TriggerServerEvent('fw_admin:goTo', target)
```

```lua
--- Networked. hours is a whole number. 0 does not expire.
---@param target integer
---@param hours integer
TriggerServerEvent('fw_admin:ban', target, hours)
```

```lua
--- Networked. false on the end forces the tool off. Delete does that for no clip.
---@param tool string
---@param force boolean|nil
TriggerServerEvent('fw_admin:self', tool, force)
```

### Replies to the client

Networked, server to one player. The screen sends these after the check. Another script should not trigger them. If you need to move, give, or ban, do that in your own script with your own check.

| Event | Who receives it | Arguments |
| --- | --- | --- |
| `fw_admin:playerList` | The admin | A list of `{ id, name, cash }`, or false when they may not see it. `cash` is the dollars they are carrying, or missing when cash cannot be read. |
| `fw_admin:doMove` | The player who is moving | `x`, `y`, `z`, `heading` |
| `fw_admin:doFreeze` | The player being frozen | `toggle` |
| `fw_admin:doHeal` | The player being healed | `stamina` |
| `fw_admin:doRevive` | The player being revived | None |
| `fw_admin:doSpectate` | The admin | `target`, or `0` to stop |
| `fw_admin:doSelf` | The admin | `tool`, `on` |
| `fw_admin:doTeleportWaypoint` | The admin | None |
| `fw_admin:doCopy` | The admin | `kind` |
| `fw_admin:openSelf` | The admin | None. Opens the small self menu. |
| `fw_admin:storeData` | The admin | The shop list, and one shop when a read or a save just finished. |

```lua
--- Networked. Sent by the server after a player action it allowed.
---@param x number
---@param y number
---@param z number
---@param heading number|nil
TriggerClientEvent('fw_admin:doMove', source, x, y, z, heading)
```

### fw_admin:teleportWaypoint

Networked, client to the server. Asks to teleport that player to their own map waypoint. The server ignores it unless `IsAdmin` is yes for whoever sent it. The admin screen sends this itself. `/tpm` checks `fw.admin` and then does the same move.

```lua
--- Networked. Sent by the admin screen. The server ignores it unless IsAdmin is yes for the sender.
TriggerServerEvent('fw_admin:teleportWaypoint')
```

### fw_admin:doTeleportWaypoint

Networked, server to the client. Moves that player to their own map waypoint. It is sent back automatically after a `fw_admin:teleportWaypoint` from an admin. If that player has no waypoint set, or the ground under it cannot be found, their F8 log says so and nothing moves.

```lua
--- Networked. Sent automatically by fw_admin after a valid fw_admin:teleportWaypoint.
---@param source integer the player to move
TriggerClientEvent('fw_admin:doTeleportWaypoint', source)
```

## State bags

This resource does not set one.
