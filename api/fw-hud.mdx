---
title: "fw_hud"
description: "Custom cores HUD, metabolism, needs, consumables, and vitals API."
---

Runs on the client for the rings and metabolism, and on the server for layout, needs, and consumable use. This is the custom HUD. It replaces the game's native cores while a character is selected. Health, stamina, hunger, thirst, temperature, and horse cores are drawn.

The HUD stays hidden until the character is in the world and outer health has stopped climbing (creator HoldVitals). That way the rings appear at their real values instead of filling on screen.

Metabolism drains hunger and thirst over time, chips the stamina core when the outer bar empties, starves outer health at 0 needs, and registers consumables from `shared/items.lua` through [fw_inventory](/api/fw-inventory) `RegisterUsable`. Stress and temperature run when their config blocks are enabled.

While a character is selected it also blocks the stock reveal-HUD path (Alt / the same control Tab often trips) and keeps the top cash widget faded out. Turn those off with `FWConfig.suppressNativeRevealHud` and `FWConfig.hideNativeCash` in `shared/config.lua` if you need the base game chrome back.

The minimap stays hidden by default. Press Alt to show it for `FWConfig.minimap.peekMs` (5000 ms). Set `FWConfig.minimap.hidden` to `false` to leave the minimap on all the time.

`source` is the client id of the player who triggered the event. `nil` means there is no value.

Close the satchel, the shop, and the admin screen before you open the settings panel. The HUD page takes mouse focus while that panel is open.

Heal and revive in [fw_admin](/api/fw-admin) call `FillVitals` on this resource when it is started. Prefer these exports from your own scripts too, so the rings and the game ped stay in sync.

## Server exports

### IsReady

Runs on the server. Yes after the settings table exists and the resource has checked in with [fw_core](/api/fw-core).

```lua
--- True when a layout can be loaded or saved.
---@return boolean
exports.fw_hud:IsReady()
```

```lua
while not exports.fw_hud:IsReady() do
    Wait(100)
end
```

### FillVitals

Runs on the server. Tells that player's client to fill outer health and the health core. Pass `true` as the second argument to fill outer stamina and the stamina core as well.

```lua
--- Fills health. With includeStamina true, stamina is filled too.
---@param source integer
---@param includeStamina boolean|nil
---@return boolean ok
---@return string|nil err
exports.fw_hud:FillVitals(source, includeStamina)
```

```lua
local ok, err = exports.fw_hud:FillVitals(source, true)
if not ok then
    print(err)
end
```

### SetHealthOuter / SetStaminaOuter

Runs on the server. Sets that player's outer bar to a 0–100 percent of max.

```lua
--- Outer health as a percent of max.
---@param source integer
---@param pct number
---@return boolean ok
---@return string|nil err
exports.fw_hud:SetHealthOuter(source, pct)
```

```lua
--- Outer stamina as a percent of max.
---@param source integer
---@param pct number
---@return boolean ok
---@return string|nil err
exports.fw_hud:SetStaminaOuter(source, pct)
```

```lua
exports.fw_hud:SetHealthOuter(source, 75)
exports.fw_hud:SetStaminaOuter(source, 50)
```

### SetHealthCore / SetStaminaCore

Runs on the server. Sets that player's inner core to 0–100.

```lua
--- Health core 0-100.
---@param source integer
---@param value number
---@return boolean ok
---@return string|nil err
exports.fw_hud:SetHealthCore(source, value)
```

```lua
--- Stamina core 0-100.
---@param source integer
---@param value number
---@return boolean ok
---@return string|nil err
exports.fw_hud:SetStaminaCore(source, value)
```

```lua
exports.fw_hud:SetHealthCore(source, 100)
exports.fw_hud:SetStaminaCore(source, 80)
```

### SetNeed / AddNeed

Runs on the server. Changes hunger, thirst, or stress on that client's metabolism. `SetNeed` writes an absolute 0–100 value. `AddNeed` adds a delta (negative drains).

```lua
--- Sets one need for a connected player.
---@param source integer
---@param name string 'hunger' | 'thirst' | 'stress'
---@param value number
---@return boolean ok
---@return string|nil err
exports.fw_hud:SetNeed(source, name, value)
```

```lua
--- Changes one need for a connected player by a delta.
---@param source integer
---@param name string 'hunger' | 'thirst' | 'stress'
---@param amount number
---@return boolean
exports.fw_hud:AddNeed(source, name, amount)
```

```lua
exports.fw_hud:SetNeed(source, 'hunger', 100)
exports.fw_hud:AddNeed(source, 'thirst', -10)
```

### Show / Hide

Runs on the server. Forces that client's custom HUD on or off. Hide wins over the normal character-selected show. Clear it with Show when you are done.

```lua
--- Clears a forced hide so the HUD can show again.
---@param source integer
---@return boolean ok
---@return string|nil err
exports.fw_hud:Show(source)
```

```lua
--- Hides the custom HUD for that player.
---@param source integer
---@return boolean ok
---@return string|nil err
exports.fw_hud:Hide(source)
```

```lua
exports.fw_hud:Hide(source)
-- cutscene…
exports.fw_hud:Show(source)
```

Outer values are 0–100 percent of max. Core values are 0–100.

```lua

exports.fw_hud:SetStaminaCore(value)

exports.fw_hud:AddStaminaOuter(pct)

exports.fw_hud:GetHealthOuter()
exports.fw_hud:GetStaminaOuter()
exports.fw_hud:GetHealthCore()
exports.fw_hud:GetStaminaCore()
```

```lua
local health = exports.fw_hud:GetHealthOuter()

    exports.fw_hud:AddHealthOuter(25)
```

### Horse (read)

The game owns horse drain. These return the last snapshot the HUD drew, or `nil` when the player is not on a horse.

```lua
exports.fw_hud:GetHorseHealthOuter()
exports.fw_hud:GetHorseHealthCore()
exports.fw_hud:GetHorseStaminaOuter()
```

### Exhaustion and temperature

```lua
--- True while outer stamina emptied and the stamina core was chipped.
---@return boolean
exports.fw_hud:IsExhausted()
```

```lua
--- Adds a temporary temperature offset for a number of seconds.
---@param amount number
---@param seconds number
---@return nil
exports.fw_hud:AddTemperatureModifier(amount, seconds)
```

```lua
--- Felt temperature in Celsius (before unit display).
---@return number
exports.fw_hud:GetTemperature()
```

The temperature icon uses `FWConfig.temperature`. Set `enabled` to `false` to hide the icon and stop cold / heat damage. `unit` is `C` or `F` for the number under the icon. `min`, `max`, and `comfort` stay in Celsius. The game native returns a float in the player's own temperature setting; `fw_hud` converts that to Celsius for the thresholds, then to `unit` for the label.

## State bags

While a character is selected, the client writes these on `LocalPlayer.state` (replicated):

| Key | Meaning |
| --- | --- |
| `hunger` | 0–100 |
| `thirst` | 0–100 |
| `stress` | 0–100 |

Read them from another resource if you only need the number. Change them through `SetNeed` / `AddNeed` so the HUD and the save path stay consistent.

## Commands

These run on the client for the player who typed them. They do nothing until a character is selected.

| Command | What it does |
| --- | --- |
| `/hud` | Hides or shows the custom HUD. |
| `/hudsettings` | Opens the layout editor. Type it again, or press Cancel, to close without saving. |

The words are `FWConfig.commands` in `shared/config.lua`.

## Events

### fw_hud:requestLayout

Networked. The client asks the server for this account's saved layout after a character is selected. You do not call this from another resource.

### fw_hud:layout

Networked. Sent to one client. The argument is the layout table to draw. When there is no saved row, or the layout version changed, the server sends the default from config.

### fw_hud:saveLayout

Networked. The client sends the layout table from the editor. The server stores it on `fw_players.id`. Oversized or empty tables are refused. Saves are rate limited.

### fw_hud:resetLayout

Networked. The client asks the server to delete this account's saved layout. The editor then shows the default layout again. Save is still required if the player wants that default written back later.

### fw_hud:fillVitals / setHealthOuter / setStaminaOuter / setHealthCore / setStaminaCore / setNeed / addNeed / setForcedOff

Networked. Sent to one client by the matching server export. Prefer the export from your script; these names are the wire underneath.

### fw_hud:staminaExhausted

Local client event. Fires when outer stamina hits empty and the stamina core is chipped. The argument is the new core value.

```lua
AddEventHandler('fw_hud:staminaExhausted', function(coreValue)
end)
```

### Consumable flow

Networked. The server registers each name in `FwHudConsumables`. Use from the satchel starts `fw_hud:useItem` on the client. When the progress finishes, the client sends `fw_hud:finishItem`. The server removes the item (unless `keep`), then sends `fw_hud:applyItem` so the client applies `needs`, `heal`, `gold`, `temp`, and `screenFx`. Cancel with `fw_hud:cancelItem`. Amounts always come from the shared config on the server path — the client does not invent rewards.

## Layout

A layout has `scale`, `opacity`, `grid`, `shape`, `version`, and `elements`. Each element has a position in percent of the screen, a size, and the fields that element uses. Health, stamina, hunger, thirst, horse health, and horse stamina are rings with state art from `img/`. Logo and clock are optional.

Raise `FWConfig.layoutVersion` in `shared/config.lua` when you change the default layout and want every account to start over.

`FWConfig.spawnReady` controls how long the client waits after character select before showing rings (`sampleMs`, `stableSamples`, `timeoutMs`).

## Metabolism config

`FWConfig.cores`, `hunger`, `thirst`, `starving`, `death`, `horse`, `stress`, `temperature`, `smoking`, and `notifications` live in `shared/config.lua`. Consumable rows are `FwHudConsumables` in `shared/items.lua`. Animations are `FwHudAnimations` in `shared/animations.lua`.

Item names must exist in `fw_items`. A seed list is `sql/consumable_items.sql`. Missing names warn at register time and skip that usable.

## Tables

Do not write these from your script. The commands and the editor are the calls.

`fw_hud_settings` is one row per account. `player_id` is `fw_players.id`. `layout` is the JSON layout.

`fw_hud_needs` is one row per character. `character_id` is `fw_characters.id`. `hunger`, `thirst`, and `stress` are 0–100. The columns are on the [database](/api/database) page.
