---
title: "fw_loading"
description: "Covers the screen from the moment someone connects until the character list is ready, and again after they pick a character until that ped is dressed."
---

Runs in the player's game. Two covers:

- From the moment someone connects until the character list is on screen. That page starts with them. It is not a second card stacked on the game's own screen.
- After they pick a character, or finish creating one, until the body, clothes, and weapons are on.

Leave `FWConfig.cutscenes` empty to keep the connect page dark. A name in that list, such as `Cutscene_MpIntro`, plays that game cutscene before the character list, under the words. Several names pick one for the visit. The connect page background is clear in that case, so the cutscene shows through the words. The revolver-cylinder prompt runs with it, and the page draws a ring in the same corner because the page sits over the game prompt. The words stay on top. The cutscene stops when the character list opens. After a character is chosen, the cover is the loading card.

`FWConfig.video` is a file in this resource, such as `html/intro.webm`. It plays behind the words only when `cutscenes` is empty. A missing file is written once in the server window, and the words stay. `minHoldMs` is the shortest the spawn cover stays up, in milliseconds. `maxWaitMs` is how long to wait for the clothes and the weapons before showing them anyway. `sceneWaitMs` is how long to stream the spawn, in milliseconds. The stream also stops when the ground around the player is loaded. `sceneRadius` is how far around the spawn to stream, in metres. The cover puts the ped back on screen after the card comes down. A visible set while the card is up does not remain.

`fw_core` hands those words over before it lets the player in. The page closes when the character list is ready to be seen: it calls `loadingComplete`, and that call runs `ShutdownLoadingScreenNui`.

`fw_creator` already calls these when a character is chosen. Use them yourself when you move someone a long way and need the same cover.

## Calls

`Show`, `Hide`, `ReleaseConnectScreen`, `StreamScene`, and `MaxWaitMs` run in the player's game. `Handover` runs on the server.

### Show

Puts the cover up. `kind` is `connect` or `spawn`. Anything else is treated as `spawn`. Calling it again for the same kind does not restart the timer.

On connect, the loadscreen page is already up. This call does not stack a second card on it. When a cutscene is set, connect plays that cutscene under the page. `spawn` is the loading card. It does not play the cutscene.

```lua
--- Shows the connect or spawn cover.
---@param kind string connect or spawn
---@return nil
exports.fw_loading:Show(kind)
```

```lua
exports.fw_loading:Show('spawn')
```

### Hide

Takes the cover down. If it has been up for less than `minHoldMs`, this call waits out the rest. Safe to call when nothing is showing.

```lua
--- Hides the cover, after the minimum hold.
---@return nil
exports.fw_loading:Hide()
```

```lua
exports.fw_loading:Hide()
```

### ReleaseConnectScreen

Asks the connect page to close, once the character list is ready to be seen. The page answers `loadingComplete`, which shuts the page down. If that answer does not come within about two seconds, this call shuts the page down itself. It does not wait past that.

```lua
--- Closes the connect page so the character list can fade in.
---@return nil
exports.fw_loading:ReleaseConnectScreen()
```

```lua
exports.fw_loading:ReleaseConnectScreen()
```

### Handover

Runs on the server, during `playerConnecting`. `deferrals` is the join handshake. `playerId` is the player's number for this visit. Call it before `deferrals.done`, or the connect page never receives the words. `fw_core` already does this on the way in. A script that replaces that check has to call it too.

The page receives the player's name, the server name, `gamemode`, `title`, `subtitle`, the video file name when one is set, and whether a cutscene is configured. A cutscene makes that page clear.

```lua
--- Hands the connect page its words. Call this before deferrals.done.
---@param deferrals table
---@param playerId integer
---@param fallbackName string|nil
---@return nil
exports.fw_loading:Handover(deferrals, playerId, fallbackName)
```

```lua
AddEventHandler('playerConnecting', function(playerName, _setKickReason, deferrals)
    deferrals.defer()
    Wait(0)
    exports.fw_loading:Handover(deferrals, source, playerName)
    deferrals.done()
end)
```

### StreamScene

Streams the world around a point. `x`, `y`, and `z` are metres. It stops when that spot is loaded, when the ground around the player is loaded, or when `sceneWaitMs` runs out. Comes back yes when the spot loaded.

```lua
--- Streams the world around a spawn.
---@param x number
---@param y number
---@param z number
---@return boolean loaded
exports.fw_loading:StreamScene(x, y, z)
```

```lua
local loaded = exports.fw_loading:StreamScene(x, y, z)
if not loaded then
    print('the spot did not finish streaming')
end
```

### MaxWaitMs

How long a spawn may wait for clothes and weapons, in milliseconds. A bad config value comes back as `15000`.

```lua
--- The spawn wait, in milliseconds.
---@return integer
exports.fw_loading:MaxWaitMs()
```

```lua
local waitMs = exports.fw_loading:MaxWaitMs()
```

## Messages

The cover listens for these. It does not send them. They are documented on the resource that sends them.

- [fw_creator:bodyReady](/fw-creator#messages-the-menu-uses) — the saved body is on the ped. The cover waits for this first.
- [fw_clothing:applied](/fw-clothing#fw_clothingapplied) — the clothes are on, or there were none. `fw_creator:bodyBare` means the same thing.
- [fw_creator:appearanceReady](/fw-creator#messages-the-menu-uses) — the cover asks for the weapon kit, after the body and the clothes.
- [fw_weapons:kitApplied](/fw-weapons#fw_weaponskitapplied) — the kit is on the current ped. The cover comes down after this, or when the wait runs out.
