Some calls run on the server. Most run in the player's game. Read the clothes a character is wearing, replace them, or toggle a piece on their body. The saved clothes live on the character. This resource writes them with `SetClothing` from [fw_characters](/fw-characters).

The shop still uses the old `murphy_clothing` and `murphy_clothes` event names. A new script should use the calls on this page. The shop itself is Murphy's clothing menu, used here under its own license — see [Scope](/#scope) on the overview page.

Cash lives on [fw_money](/fw-money). This shop still does not take any dollars. A later change can call `RemoveCash`. Job-locked categories stay hidden because there is no job.

`fw_creator` must keep `Config.murphy_clothing` true.

## Clothing document

```lua
{
    clothes = {
        hats = { model = 12, texture = 1 },
    },
    outfitId = '1234567', -- '0' when no saved outfit is worn
    outfits = {},
    wearable = {},
}
```

`clothes` is what the ped is wearing. Hair and beard stay on the barber document, not here. `outfitId` is the saved outfit, or `'0'`.

A write only works while that player is online and has this character selected.

## Calls on the server

### IsBandanaEquipped

Runs on the server. Yes when the worn clothes include a mask (`masks`) or a large mask (`masks_large`) with a model number above 0.

```lua
--- True when this player is wearing a mask or a large mask.
---@param source integer
---@return boolean
exports.fw_clothing:IsBandanaEquipped(source)
```

```lua
if exports.fw_clothing:IsBandanaEquipped(source) then
    -- hide the face from other players
end
```

### GetPlayerClothes

Runs on the server. The worn clothes, turned into the numbers the game uses to draw them. You get an empty result when nothing is saved, or when a clothing slot has no matching picture in the catalog.

```lua
--- Worn clothes as asset hashes, keyed by category.
---@param source integer
---@return table clothes
exports.fw_clothing:GetPlayerClothes(source)
```

Most pieces come back as `{ hash, tint0, tint1, tint2 }`. A piece that is drawn from a story-mode model instead of a regular multiplayer item also carries `drawable`, `albedo`, `normal`, `material`, and `palette`, so check for those keys rather than assuming every category has them.

```lua
local clothes = exports.fw_clothing:GetPlayerClothes(source)
local hat = clothes.hats
if hat ~= nil then
    print(hat.hash)
end
```

### GetPlayerTemperatureProtection

Runs on the server. How many warm pieces and cold pieces are worn, and the protection numbers from the clothing settings.

```lua
--- Warm and cold clothing counts for the active character.
---@return table protection
exports.fw_clothing:GetPlayerTemperatureProtection(source)
```

```lua
{
    warmItems = 0,
    coldItems = 0,
    coldProtection = 3,
    heatProtection = 3,
}
```

```lua
local protection = exports.fw_clothing:GetPlayerTemperatureProtection(source)
print(protection.coldProtection)
```

### SetClothesForChar

Runs on the server. Saves clothes for the character that is selected right now, then puts them on that player. This is the call a job or uniform script should use.

```lua
--- Saves worn clothes for the online player who has this character selected.
--- False and a reason when the character is offline or an entry is not a model and texture.
---@param charid integer|string
---@param clothes table
---@param outfitId integer|string|nil
---@return boolean ok
---@return string|nil err
exports.fw_clothing:SetClothesForChar(charid, clothes, outfitId)
```

`charid` is `fw_characters.id`. `clothes` is `{ hats = { model = 12, texture = 1 } }`. `model` is the catalog index. `texture` is a number, or a table `{ palette, tint0, tint1, tint2 }`. Hair and beard are removed from the table before it is saved. Leave `outfitId` out to store no saved outfit.

| `err` | When |
| --- | --- |
| `SetClothesForChar: charid is required` | The character id is missing. |
| `SetClothesForChar: clothes must be a table { category = { model, texture } }` | `clothes` is not a table. |
| `SetClothesForChar: invalid entry for category '<category>' ...` | That category has no numeric `model`. |
| `SetClothesForChar: invalid texture for category '<category>'` | `texture` is not a number or a table. |
| `SetClothesForChar: that character is not selected by an online player` | Nobody online is playing that character. |
| `SetClothesForChar: could not save clothing` | `SetClothing` failed. |

```lua
local ok, err = exports.fw_clothing:SetClothesForChar(characterId, {
    hats = { model = 12, texture = 1 },
}, nil)
if not ok then
    print(err)
    return
end
```

## Calls in the player's game

These run on the player's computer. `source` is not passed. They look at the clothes already loaded for the character they are playing.

A category is one clothing slot. The names you will use most are `hats`, `shirts_full`, `vests`, `boots`, `neckwear`, `masks`, and `gunbelts`.

### AreClothesStillApplied

Runs in the player's game. Yes when the clothes this resource last put on them are still there. No if clothes were never loaded this visit, or one slot is missing. The check skips `bodies_upper` and `bodies_lower` (those are the body, not clothes), and treats `neckwear` and `neckerchiefs` as the same slot, since the game stores either name under the other. The character menu uses this after it applies a body, to see if the clothes were wiped off.

```lua
--- True when the last clothes this resource applied are still on the ped.
---@return boolean
exports.fw_clothing:AreClothesStillApplied()
```

```lua
if not exports.fw_clothing:AreClothesStillApplied() then
    TriggerEvent('murphy_clothing:loadclothes')
end
```

### IsPlayerNaked

Runs in the player's game. Yes after `SetNaked(true)` or `ToggleNaked` has stripped them to the base body. No when their clothes are on.

```lua
--- True when this player has been set naked by the clothing script.
---@return boolean
exports.fw_clothing:IsPlayerNaked()
```

```lua
if exports.fw_clothing:IsPlayerNaked() then
    return
end
```

### ToggleNaked

Runs in the player's game. Switches between the base body and the saved clothes. Pass `true` to also show the small notice. You get back the new naked state.

```lua
--- Toggles the base body. Pass true to show the notice.
---@param notify boolean|nil
---@return boolean naked
exports.fw_clothing:ToggleNaked(notify)
```

A bathhouse script strips them, then puts the clothes back when they leave:

```lua
exports.fw_clothing:ToggleNaked(false)
```

The same action is the message `murphy_clothing:toggleNaked`. It stays in the player's game.

```lua
TriggerEvent('murphy_clothing:toggleNaked', false)
```

### SetNaked

Runs in the player's game. `naked` true strips to the base body. `naked` false puts the saved clothes back. `notify` true shows the notice.

```lua
--- Sets the base body on or off.
---@param naked boolean
---@param notify boolean|nil
---@return boolean naked
exports.fw_clothing:SetNaked(naked, notify)
```

```lua
exports.fw_clothing:SetNaked(true, false)
```

The same action is `murphy_clothing:setNaked` in the player's game:

```lua
TriggerEvent('murphy_clothing:setNaked', true, false)
```

`murphy_clothing:getNakedState` is the old message for the same check as `IsPlayerNaked`. It does not hand the answer to the script that sent it. Use the call.

Runs in the player's game. One category: `category`, `model`, `texture`, and `temperature` (`warm`, `cold`, or `neutral`). You get nothing when that slot is empty.


### GetTemperatureProtection

Runs in the player's game. The same kind of result as the server call, plus `categories`, the list of worn category names. A cold-weather script on the player's computer can read it without asking the server.

```lua
--- Warm and cold counts for the clothes on this computer.
---@return table protection
exports.fw_clothing:GetTemperatureProtection()
```

```lua
local protection = exports.fw_clothing:GetTemperatureProtection()
if protection.coldProtection == 0 then
    print('no coat')
end
```

### GetClothingToggleState

Runs in the player's game. Ask about a list of categories. For each one you get `owned` (the outfit includes it) and `on` (it is showing right now). `fw_weapons` uses this to see the gunbelt.

```lua
--- owned and on, for each category name you pass.
---@param categories string[]
---@return table states
exports.fw_clothing:GetClothingToggleState(categories)
```

```lua
local states = exports.fw_clothing:GetClothingToggleState({ 'gunbelts' })
local belt = states.gunbelts
if belt ~= nil and belt.on then
    print('belt is on')
end
```

### ToggleClothingCategory

Runs in the player's game. Takes that saved piece off, or puts it back on. Works for any category the outfit owns, not only the ones listed under `ToggleClothingComponent` below. You get yes when it is on afterwards. You get no when the outfit has no such piece.

```lua
--- Toggles one saved category. False when the outfit has none.
---@param category string
---@return boolean on
exports.fw_clothing:ToggleClothingCategory(category)
```

```lua
local on = exports.fw_clothing:ToggleClothingCategory('hats')
```

The message `murphy_clothes:Equip-UnequipCategory` does the same toggle. It stays in the player's game.

```lua
TriggerEvent('murphy_clothes:Equip-UnequipCategory', 'hats')
```

### ToggleClothingComponent

Runs in the player's game. The wheel uses this to take a piece off or put it back, with a short matching animation (reaching for the hat, adjusting the belt, and so on). Only a fixed list of categories can be toggled this way: `hats`, `masks`, `eyewear`, `headwear`, `hat_accessories`, `neckwear`, `neckerchiefs`, `neckties`, `shirts_full`, `vests`, `suspenders`, `coats`, `coats_closed`, `coats_heavy`, `cloaks`, `ponchos`, `capes`, `gloves`, `gauntlets`, `gunbelts`, `gunbelt_accs`, `pants`, `chaps`, `spats`, `boots`, `boot_accessories`, `accessories`, `satchels`, `badges`, and `aprons`. Anything outside that list, or a category name that is not a string, is refused. You also get no while another toggle's animation is still playing, or while the player is dead. Otherwise you get yes — the toggle has started, even if that slot turns out to already be empty.

```lua
--- Toggles the piece in this category on the player's body.
---@param category string
---@return boolean ok
exports.fw_clothing:ToggleClothingComponent(category)
```

```lua
exports.fw_clothing:ToggleClothingComponent('gloves')
```

The message `murphy_clothing:toggleComponent` is the same call. The command `/toggleclothing hats` is the same call from chat.

```lua
TriggerEvent('murphy_clothing:toggleComponent', 'hats')
```

### GetSatchelPieceActions

Runs in the player's game. The bag screen asks this so it only shows Roll sleeves, or Tuck boots, when that piece can do it.

`slots` is a map. The key is a name you choose, such as `shirt`. The value is a list of category names to look at. You get back only the slots that have an action. A slot can include `collar`, `bandana`, `tuck`, or `variation`.

```lua
--- Which extra actions the worn pieces support.
---@param slots table
---@return table actions
exports.fw_clothing:GetSatchelPieceActions(slots)
```

```lua
local actions = exports.fw_clothing:GetSatchelPieceActions({
    shirt = { 'shirts_full' },
    neckwear = { 'neckwear', 'neckerchiefs' },
})
if actions.shirt ~= nil and actions.shirt.collar then
    exports.fw_clothing:ToggleCollar()
end
```

### EquipMultipleClothes

Runs in the player's game. Puts several pieces on at once. This changes what they are wearing right now. Saving that outfit for later is `SetClothesForChar` on the server.

`clothesData` is `{ hats = { model = 1, texture = 0 } }`. `tint0`, `tint1`, and `tint2` are optional. Leave `ped` out to use the player's character. You get no when `clothesData` is not a table. A category or model that does not exist in the catalog is skipped quietly — `ok` only reports whether `clothesData` itself was a table, not whether every piece in it was understood, so check the result with `GetEquippedCategories` afterwards if you need to be sure something was actually applied.

```lua
--- Puts several pieces on a character in this player's game.
---@param clothesData table
---@param ped integer|nil
---@return boolean ok
exports.fw_clothing:EquipMultipleClothes(clothesData, ped)
```

A costume script on the player's computer:

```lua
exports.fw_clothing:EquipMultipleClothes({
    hats = { model = 1, texture = 0 },
    shirts_full = { model = 5, texture = 2 },
})
```

The message `murphy_clothes:EquipMultipleClothes` is the same call.

```lua
TriggerEvent('murphy_clothes:EquipMultipleClothes', {
    hats = { model = 1, texture = 0 },
})
```

## Messages

A message on the server is heard with `AddEventHandler`. A message in the player's game is heard with `AddEventHandler` when it stays there, or `RegisterNetEvent` when the server can send it. Your script hears one only if it is already running. Put the listener at the top of your script.

### murphy_clothing:clothesUpdated

Stays on the server. Sent after clothes are saved, from the shop or from `SetClothesForChar`. A uniform script can wait for this, then read the clothes back:

```lua
---@param source integer
---@param charid integer
---@param clothes table
AddEventHandler('murphy_clothing:clothesUpdated', function(source, charid, clothes)
    print(charid)
end)
```

### murphy_clothing:loadclothes

Sent from the server to the player's game. Their game puts the saved clothes back on. The character menu sends the local version of this after a body is applied. You can send it yourself after you know the clothes were wiped off:

```lua
TriggerEvent('murphy_clothing:loadclothes')
```

### murphy_clothes:OnClothingChanged

Stays in the player's game. Sent when a category is taken off or put on. `category` is the slot name. `equipped` is yes when it is on. `fw_weapons` listens so a missing gunbelt puts the guns away.

```lua
---@param category string
---@param equipped boolean
AddEventHandler('murphy_clothes:OnClothingChanged', function(category, equipped)
    if category == 'gunbelts' and not equipped then
        print('belt off')
    end
end)
```

### fw_clothing:sleeveChanged

Stays in the player's game. Sent after the sleeve or collar changes. It has no extra information. Read `IsSleeveRolled` if you need the new state.

```lua
AddEventHandler('fw_clothing:sleeveChanged', function()
end)
```

### Bandana and temperature messages

These stay in the player's game. The calls above are the easier way. The messages exist so an older script can ask without a call.

| Message | What it does | What to do |
| --- | --- | --- |
| `murphy_clothes:CheckBandana` | Looks at the mask, then sends `murphy_clothes:BandanaStatus`. | Prefer `IsBandanaEquipped`. |
| `murphy_clothes:BandanaStatus` | `true` when a mask is on. | Listen if you sent `CheckBandana`. |
| `murphy_clothes:ToggleBandana` | `state` true means the bandana is up. Also sends `syn_robbery:bandana`. | Prefer `ToggleNeckwearUp`. |
| `murphy_clothes:GetTemperatureProtection` | Then sends `murphy_clothes:TemperatureProtectionData`. | Prefer `GetTemperatureProtection`. |
| `murphy_clothes:TemperatureProtectionData` | The protection table. | Listen if you sent the ask above. |
| `murphy_clothes:TemperatureUpdate` | The protection table, sent about half a second after clothes change. | Listen to follow warmth as they dress. |

```lua
AddEventHandler('murphy_clothes:TemperatureUpdate', function(protection)
    print(protection.coldProtection)
end)
```

## State bags

This resource does not set one. The character id is `fwCharacterId` on [fw_characters](/fw-characters).

## Commands

| Command | Who | What it does |
| --- | --- | --- |
| `/loadclothes` | The player | Puts the saved clothes back on. |
| `/undress` | The player | Takes off every clothing piece except the body itself (hair, beard, skin, and so on stay). |
| `/getnaked` | The player | Same switch as `ToggleNaked(true)` — strips to the base body, or puts the saved clothes back, with a small notice either way. An optional keybind does the same thing if the server sets `Config.ClothesManagement.GetNakedKeybind`. |
| `/toggleclothing <category>` | The player | Same toggle as `ToggleClothingComponent`. |
| `/ClothesManagement` | A player who has `fw.admin` (see [fw_admin](/fw-admin)) | Opens the wearable/body management menu. The name comes from `Config.ClothesManagement.Command`; an optional keybind (`Config.ClothesManagement.Keybind`) opens the same menu. |
| Whatever name the server sets in `Config.MenuCommand` | A player who has `fw.admin` | Opens the outfit shop list. There is no command here unless the server sets this config value — it is nil by default. |
